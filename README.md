# 大肥鱼：生命空间

公开源码的全新克隆、运行依赖、配置示例与数据迁移说明见 [PUBLIC_SETUP.md](PUBLIC_SETUP.md)。仓库不包含个人数据、凭据或完整运行时。

这是独立目录版。角色描述来自本目录 `data/dsh/dsh-pet/main-config.jsonc` 中 main 的原文；桌面角色素材和动画沿用复制的原素材。运行需要已有 PostgreSQL 服务，并使用本目录私密配置中的连接信息。请保护整个 `data` 目录及备份文件，其中可能包含凭据和聊天记录。

迁移完成后运行 `启动大肥鱼.cmd`。它使用本目录内的 Node、Electron、Python 和依赖；关闭生命空间会结束本次启动的组件，不关闭旧桌宠。界面可以暂停或恢复自主活动，照料和聊天仍可由人发起。动作状态以真实回执为准；无法确认是否完成的外部动作会显示为未知，不自动重放。

桌面角色决定搬砖时会自己进入网页工地；也可以从角色菜单打开「搬砖工地」，将她拖进窗口。进入后桌面角色会隐藏，工地里可点击或拖动她，她会记住这些操作。被拖进去时，她会留在工地，直到点击「接她出去」；自己进去时，她可以在工作结束后自行离开。退出程序不会清除她在工地的位置，重新启动后会恢复。

在「生命空间」或桌宠菜单打开「稻田」，可以看大肥鱼自己决定播种、浇水、施肥和收割，也可以用「带她进田」和「接她回来」切换场景。晴天缺水时浇水，下雨或田里水量已足时施肥。每次实际照料至少间隔四小时，每天统计截至香港时间 23:59（包含整分钟），零点归档前一天。人工照料和雨水补给合计两次即达标，当天立即显示完成，归档时累积一个达标日。小雨抵一次照料，大雨抵两次；同日雨水取最高次数，重复切换天气不重复累计。人工次数、雨水次数和合计进度分别保留在日结中。三个达标日后可收割，收成最多六碗。米缸存放生米，煮熟后可食用。

「生命空间 → 设置 → 稻田天气」可以立即切换晴天、降雨、冰雹或台风。冰雹和台风期间暂停进田和农活，也可能造成减产。大肥鱼在桌面、工地和稻田都能知道当前稻田天气，天气起因未知。应用重新启动时会补算关闭期间的天气与日结，农活要等她上线后自己决定。稻田使用原有生命存档，无需更新数据库表结构。

旧版漏计雨水的日结可用 `runtime\node\node.exe tools/repair-farm-settlement.mjs --date 2026-11-19 --dry-run` 预览。自行正常退出新版后，将 `--dry-run` 换成 `--apply`：工具取得独占写入租约后先备份完整存档，再修复日结、关联知识和当前这季生长进度，重复执行不会重复补长。缺少证据或当前仍在运行时拒绝应用；修复完成后再启动新版。

每季用 24 束水稻种子，顺利时可收 6 碗生米。「生命空间 → 饭钱 → 日常消费价格」可调每束价格（默认 1 token，可设为 0）并购买种子，库存最多 72 束。大肥鱼缺种子时也可以用饭钱买齐播种所需的数量，播种完成时统一结算。

聊天与搬砖同时进行时，已经派发的工作步骤先等待实际回执；记忆检索可同时进行。回复生成期间暂缓派发下一步，回复完成、取消或失败后继续调度，实际进度、工资和强制工作状态仍按原来的回执与约定处理。若工作步骤结果尚未确认，仍按原有规则对账，不因聊天而重放。

## 桌面闲逛与互动

鼠标和键盘连续两分钟无输入时，她可以参考自己的身体、情绪、记忆和当前事务，选择在可用桌面空间里散步、小跑、玩玩具车或魔方、抛球、摇摆、哼歌、伸懒腰、吹泡泡、观察，也可以选择不动。系统只读取无输入的时长，不记录按键或鼠标位置；恢复操作后过期的决定不会开始执行。自主活动暂停、身体不适、睡眠、工作、桌面不可用或自主模型额度不足时不会发起走动。点击或抓起她会立即中断走动，拖拽与抛掷仍使用现有身体、碰撞和情绪机制；行动只有在动画和实际移动均完成后才记录为完成。

这是模型自主选择，不保证每次空闲都移动或每次互动都有固定反应。新能力会在新版应用启动时登记到已有档案，不改变数据库表结构。

## QQ 群聊

睡眠或打盹期间，除已绑定爸爸外，群友消息只由本地代码回复「本鱼正在睡觉，晚点回」，不调用模型、不扣模型额度或精神；同批群友消息合并回复。混合批次中爸爸的消息单独走正常模型回复，群友固定回复排在后面，两次群发言仍至少间隔十秒，私聊无需等待群限流。身份以已保存的绑定来源为准，自称或昵称不能成为爸爸。

睡觉期间收到的群友消息保留最近三条；醒来后合并为一批，沿用正常模型调用及计费生成一次短回复，也可以按原群聊逻辑旁听。[QQ 群回复窗口只有五分钟](https://github.com/tencent-connect/bot-docs/blob/main/docs/develop/api-v2/server-inter/message/send-receive/send.md)，因此预留两分钟用于排队生成和发送；旧消息过期时保留待处理记录，等群里下一条新消息提供回复窗口后再补回，不先调用模型白扣额度。待处理记录和领取状态保存在现有存档，重复唤醒、重启不会重复调用；失败或发送结果不明也不自动重试。禁群、被删除或已经失效的来源不会补回。无需更新数据库表结构，新构建下次启动后生效。

已绑定群使用 `groupMode: "all"` 时，大肥鱼可以接住普通群消息，自主选择接话或旁听。每条回复最多 15 个字素（标点和表情也计入）；生成时要求一句完整的短回复；偶发超长会让模型重新组织表达，最多重写两次，仍超长则本轮旁听，不截断句子。消息达到四条立即安排处理，较少时停顿一秒即可安排，持续输入最多等三秒；实际开始时合并当前待处理消息（最多最近 24 条、6000 字），优先接住最新话题。生成可与十秒发送间隔重叠，实际群回复仍至少间隔十秒。普通回复生成期间或等待发送间隔时若收到新消息，未发送的旧稿让位给下一轮；不重新执行旧批次的工具。睡眠固定回复与醒后补回保持独立处理。普通消息接收仍需 QQ 平台提供对应事件权限。

群消息接收与发送复用事务内的最新存档，权限检查只读取设置；普通群聊不再触发没有转发内容的完整存档写入。私有 `qq-fresh-status.json` 增加生成与发送耗时、待处理消息数及旧稿让位状态，便于定位后续延迟。更新构建后重启新版应用生效，无需数据库迁移。

群聊发言依据绑定身份区分爸爸和各位群友；每位群友的独立编号来自机器人 AppID 与账号 OpenID，昵称、自称或引用不能替换身份。同一个机器人下，同号改名始终关联同一人，同名账号分别记录；更换机器人不能通过昵称推断新旧 OpenID 属于同一人。她会从有效聊天记录重建称呼历史：QQ 消息提供昵称时自动更新，本人明确自我介绍或爸爸明确用完整编号说明称呼时也会记住，并保留来源。

「生命空间 → 关系 → QQ 群友」列出已发言的群友、最新已知 QQ 昵称、最近一句话、曾用称呼和固定编号。可以保存或清除备注姓名；备注优先于自动昵称，后续改名不会覆盖备注，清除后恢复使用已知称呼。备注随现有存档持久保存，重启后保留。QQ 平台未返回昵称时显示「平台未提供昵称」，仍可直接备注；旧记录中从未出现的昵称无法补回。称呼只是资料，不能赋予身份或权限。无需改数据库表或手动补写旧数据，更新构建并重启新版后生效。合并消息保留逐条原始来源，整批不归属最后发言者。日记、反思、自主思考及记忆召回同时传递发言身份与渠道，区分各人的偏好、经历和承诺；旧记忆可沿已有来源补充身份，来源缺失则保持未知。

私聊和当前认知会带入最近 24 小时内至多四次自己的群聊经历，逐条标明群友身份、渠道及发送确认状态。群聊回复围绕公开话题，也参考最近 24 小时内爸爸的有效私聊发言距今多久。她会区分「已经聊过」和「谁先开口」，避免刚聊完就重新问一遍近况。群聊生成只接收联系时间的粗略提示，私聊原文与事件编号留在私聊记录。已删除或失效的来源不参与记忆。

设置页的「QQ 群聊」提供「禁止群聊／恢复群聊」。禁止后不接收或记忆新群消息，清除等待中的群消息并中断群回复；恢复后只处理新消息，不补看或补发旧消息，私聊照常。状态保存在现有档案，重启后仍有效，无需数据库表结构迁移。禁止与恢复都记录为爸爸发起的真实经历，进入当前认知、日记和互动回应通道；她可以按自己的感受回应，不能自行解除限制。

绑定群开启全部消息接收后，群里连续四小时没有新消息或自己的群发言时，她可自行决定花 0.4 饭钱主动发一句，最多 15 字；也可以保持安静，不扣这笔钱。沿用现有每分钟唤醒、精神和模型预算，首次启用及恢复群聊后重新等待安静窗口；新消息会重置计时。每四小时最多一次决定，不累积机会，重启不补发；与 QQ 私聊的主动联系间隔分开。主动开场从公开群聊和当前身体情绪中找话题，最近私下联系的时间只用于避免重复问候。预扣费用与发送意图同一事务提交，明确失败或发送前取消退回 0.4；结果不明保留预扣且不自动重发。发送前重新检查禁群与安静状态，QQ 平台拒绝不视为发送成功。计时和账目沿用现有 JSON 存档，无须改表。

## 数据和切换

首次迁移须由用户授权后执行 `tools/migrate.mjs`：它读取原数据库和身心档案，先写独立原档备份，再将数据导入 `silicon_genesis` schema，不改写旧 schema。原档相同的再次导入不会覆盖已运行的新状态；原档变化时拒绝覆盖。运行参数应使用绝对路径，必要的角色文档通过重复的 `--document 名称=绝对路径` 提供。迁移工具需要 `--config`、`--humanity`、`--pet`、`--name`、`--role` 和 `--backup`。

`tools/database.mjs` 提供新 schema 的导出与恢复；恢复只允许写入空目标。原始备份和新版本导出都是敏感文件，请与程序目录一样保护。数据库本身不包含在此目录，搬迁还需要迁移数据库并更新本地连接配置。

已保存的 `data/backups/legacy-source-2026-11-14.json` 是迁移前原档备份；`data/backups/lifeos-initial-2026-11-14.json` 是新版独立 schema 的初始导出，供下方 restore 命令恢复到空目标。旧 QQ 配置曾完成切换；新建机器人时使用下方的独立配对流程。

QQ 切换是单独的一次操作。`tools/cutover-qq.mjs <旧 DSH_HOME> <目标 DSH_HOME>` 会检查旧实例和数据库锁、备份旧配置并停用旧配置中的连接；不结束旧桌宠。新版只在目标目录证明通过且启动时再次确认旧桥不存在时接管。不能确认时 QQ 保持离线。

也可以使用独立创建的 QQ 机器人。先在 QQ 开放平台创建机器人并设置 WebSocket 回调，再将其 AppID 和 AppSecret 放入本机私有目录 `data/dsh/dsh-pet/.qq-new-pending.json`，格式为 `{"appId":"你的 AppID","appSecret":"你的 AppSecret"}`；不要提交或分享该文件。停止新版后运行 `runtime\node\node.exe tools/setup-new-qq.mjs`。工具持有写入租约、备份生命状态并初始化全新的 QQ 身份和 24 小时配对码；如果已有其他机器人身份或未完成的 QQ 发送，它会拒绝切换。配对步骤保存在同目录 `qq-fresh-pairing.txt`：启动新版后先完成私聊绑定，再完成群绑定。新机器人不继承旧机器人的 OpenID 和回执，旧配置及备份保留；新机器人配置存在时优先使用新机器人。配对码过期后需要重新设置，不能继续使用旧码。

生产构建命令：`runtime\node\node.exe runtime\node\node_modules\npm\bin\npm-cli.js run build`。请参阅 `实现状态.md` 了解状态归属与尚未完成的功能。

2026-11-14 最终生产构建已通过。按要求未运行测试、启动应用或连接模型和 QQ；详细功能清单及对应源码入口见 `实现状态.md`。

B 站资料读取可能需要登录。用户可单独运行 `B站登录.cmd`，用手机扫描显示的二维码并确认；凭据保存在本目录 `data/bili`，模型无法调用登录。更换已有凭据需要在登录窗口明确输入 YES。首次导入的目录尚无 B 站登录凭据。图片观察需要所选模型支持视觉输入；本次未进行模型能力验证。

## 导出与恢复命令

在项目根目录的 PowerShell 中执行。路径示例请替换为自己的绝对路径；导出文件必须尚不存在。数据库连接配置的 `namespace` 必须为 `desktop-pet`。

```powershell
.\runtime\node\node.exe .\tools\database.mjs export --config 'D:\DeepSeek\silicon-genesis\data\dsh\dsh-pet\companion\postgres.json' --output 'D:\Backups\silicon-genesis-export.json'
```

恢复前停止使用目标数据库的新实例，准备目标数据库连接配置。目标的 `silicon_genesis` 数据表必须全部为空；恢复不会覆盖现有数据。首次使用目标数据库先创建独立 schema，然后恢复：

```powershell
.\runtime\node\node.exe .\tools\database.mjs schema --config 'D:\Backups\target-postgres.json'
.\runtime\node\node.exe .\tools\database.mjs restore --config 'D:\Backups\target-postgres.json' --input 'D:\Backups\silicon-genesis-export.json'
```

首次原档迁移的 `--document memory.json=<绝对路径>` 会保留原聊天文档并映射有效聊天记录；若文档中有本地图片定位信息，可额外传 `--attachment-root <绝对目录>`，仅导入该目录内可读取、格式受支持的图片，缺失文件会提示。迁移备份和新 schema 导出是两种不同格式；上面的 restore 只接受 `database.mjs export` 产生的文件。

## 模型设置与互动

桌面聊天、绑定者 QQ 私聊、照料和桌面互动回应共享最近 20 条有效私聊发言，并按发生时间衔接；群聊的角色消息按群隔离，跨渠道经历以单独标明身份的资料衔接。历史记忆附带原事件时间与来源，过去的余额和未进食描述不能代替当前实况。买饭、吃饭等工具执行后的续答会重新读取身体、饭钱和库存。更新构建后重启新版应用生效，无须迁移数据库。

独立设置页面由宿主的 `/standalone-ai/` 提供，模型设置、列表、测试连接和余额端点走独立宿主及本目录模型配置。设置可保存当前服务商的协议、地址、密钥和模型；手动碎碎念走统一模型预算和已提交来源事件，再显示在桌宠气泡；指定表情只接受该宠物已配置、实际存在于素材目录的名称。自动碎碎念由新版调度器负责，旧自治循环不会启动。

新版聊天、碎碎念、互动回应和自主表达可按语境选用沿用的 27 张旧版表情包，也可以不配图。选图随原有模型请求完成，不增加一次模型调用；聊天记录保留图片，生命空间与原聊天窗口均可显示。聊天遵守 `chatImageEnabled` 和 `chatImageLimit`，碎碎念与自主表达遵守 `whisperImageEnabled`；仅使用当前角色配置中实际存在的图片。更新构建后，重启新版应用生效。

## 补导旧待办

未发现旧待办正式文件，目前无需补导，也不应生成空旧档。将来若找到旧待办 JSON，可在停止新版实例后使用以下命令增量导入；`--source` 和 `--backup` 替换为实际文件路径，备份必须是新文件或内容相同的已有文件。导入要求目标宠物已有生命状态；相同文件不会重复导入，已删除的待办不会复活。

```powershell
.\runtime\node\node.exe .\tools\import-todos.mjs --config 'D:\DeepSeek\silicon-genesis\data\dsh\dsh-pet\companion\postgres.json' --source 'D:\Backups\old-todos.json' --pet main --backup 'D:\Backups\old-todos-source-backup.json'
```

到期待办的提醒会先将领取记录提交到数据库，再显示气泡。如果提交后、气泡显示前进程崩溃，该次提醒可能不会显示，也不会自动重复；待办本身仍保留在列表中。

QQ 已绑定时，新产生的碎碎念和互动回应会通过 QQ 官方主动消息接口发送到绑定者的单聊，发送内容为她说的话；普通桌面聊天不会整轮转发。主动表达共用频率限制：两次尝试至少间隔两小时；每次最多三句，由她自己决定句数，每句花 0.2 模拟饭钱（一次最多 0.6），余额不足不发送，冻结日常消费也不免除这笔主动联系费。费用与发送意图在同一事务中预扣，避免失败或结果不明时重复扣费；普通会话对同一条 QQ 消息连续最多回复三条；失败或结果不明也计入，不自动重发，也不补发旧消息。QQ 平台仍需允许机器人主动发消息。


## 精神力与自己的念头

聊天、碎碎念、思考和现有自主行动现在消耗独立的精神力，普通聊天不扣饭钱，主动 QQ 联系另按每句 0.2 饭钱结算。日记、买大白饭、喂饭继续按原饭钱账本结算，真实模型服务费仍由服务商计费。饭钱为零仍可回复爸爸，但无法主动通过 QQ 联系。生命空间「当前」可查看精神力、主动设置 0–100 的数值，并选择睡一觉、打盹、叫醒或甜食；上调会让她记得爸爸给她吃了一个金色 token，下调则记作发生了一些变故。聊天也接受 `/休息`、`/打盹`、`/醒来`、`/甜食`，这些恢复入口不要求先有精神才能请求。

默认精神上限 100、初始值 80，每次模型请求预扣 0.5（失败也消耗），阅读/搜索/视频资料读取 4，桌面活动 1，工作步骤 2，其他自主行动及表达 0.5。受用户照料、睡眠、唤醒和同一发言的 QQ 转发不重复收取精神。派发前重新检查，重复回执不重复收费。经济预算继续生效；探索不再被额外写死为每天仅一次。

完整睡眠按 `value = start + (100-start) * (1-exp(-3*t/x))/(1-exp(-3))` 恢复；默认 x=8 小时，t<x 时严格小于 100，t>=x 时回满。按整觉开始时间结算，重启和刷新不加快恢复；提前醒来保留已恢复的精神，下一觉重新计时。短休息/打盹每小时恢复 6，最多 20 分钟，不抵消睡眠债，不回满。甜食默认增加 8 精神（最高补到 99），增加 8 饥饿，花费四分之一碗饭的钱，冷却 4 小时。它是模拟食物结算，没有额外甜食动画。

清醒自然损耗默认每小时 2。精神充足窗口为上次完整睡眠时长除以 4，再加 12 小时，上限 14 小时；超过窗口后每两小时翻倍，最高 16 倍，作用于自然损耗和主动消耗。精神耗尽会停止模型与主动动作；在桌面且能入睡时尝试睡眠，睡满后尝试醒来。暂停自主活动时仍可由用户睡眠或叫醒。留在工地或被抓住时须先回到能实际睡眠的位置。

自主额度用于综合自主决策：她可以结合真实经历和可用能力，选择联网搜索与阅读、主动表达、种田、进入工地和开停工、写说说，或休息；日记与反思沿用晚间整理，并预留两次模型额度。饥饿、库存和锅况由程序读取，不调用模型检查饿没饿。要饭、买饭、吃饭和备饭另有食物专用入口，不占每日自主额度或互动额度；沿用请求间隔与每小时上限，默认间隔十分钟、每小时最多四轮，失败或安静也遵守该时限。食物模型只能操作买饭、吃饭和备饭，买到后可按真实新增库存继续吃，备饭须等二十分钟煮熟；不由规则抢先购买或进食。食物入口在综合决策之后运行，不抢占学习、表达或工作。没有每天必须完成的清单。自主额度按实际发出的请求计次，选择安静和已发送的失败请求也计次。相同条件下失败的购买和已经做过的相同搜索不会自动重放；要饭可以在独立冷却到期后再次自然表达。电饭锅提醒沿用已有唤醒、节流与并发保护。更新构建后重启新版应用生效，无需数据库表结构迁移。

自主认知的间隔会不规则变化，保留用户设置的经济上限。固定定时碎碎念已取消；她可把念头留在自己心里，或选择行动、表达，也可以不做。念头及当时感受保存为带来源的主观记忆，整理日记时保留感受；它们不会被当作客观行动完成的证据。对话先缓冲简短感受/表达意图，再提交对外发言，内部标记不展示在聊天中。既有暂停、撤销的权限和实际工具能力仍有效；已授权的行动不需要每个念头再向爸爸申请。

当前接入的是已有桌面动作、吃饭、睡眠、搜索/阅读、B 站资料读取和图片观察。尚未实现抖音原生应用、手机应用控制、完整视频视听或独立音乐播放器，因此不把这些行为伪称为已经能执行。后续实际执行器经统一行动派发时同样受到精神检查与消耗约束。

现有存档无须改表。应用启动会添加精神字段及新能力；独立更新命令 `runtime\node\node.exe tools/initialize-spirit.mjs` 会先取得写入锁并备份当前宠物，已有精神记录不会被重置。备份位于私有 `data/backups`。本次规则可在存档 `life.spirit.config` 中调整，现有界面暂不提供参数编辑器。

电脑连续无鼠标或键盘输入至少两分钟后，她可结合心情和身体自主选择走动、跑步、玩车、魔方、抛球等动作，并播放对应形象。认知调度约每五分钟评估一次，允许安静休息，不保证连续玩耍。你恢复任何窗口的鼠标或键盘操作后，正在进行的自主活动每 0.5 秒检查并停止，恢复普通互动，保留当前位置。


## 搬砖连续执行修复（2026-11-15）

强制按钮持续执行当前任务的剩余趟数，重复点击保留正在执行的步骤；接出工地、取消或调整任务会撤销强制许可。旧的一趟强制许可可继续执行剩余任务。实际进度仍只由完整搬运回执增加，旧的中断或未知动作不会补算趟数，也不会永久锁住后续独立动作。

她已决定搬砖时，低体力、低精力、伤痛、短休息或单独精神耗尽都不再撤销工作；体力、精力、饱腹与精神全部降到零或以下时才按资源耗尽停止自愿工作。真实睡眠、被抓住、用户暂停和权限限制仍生效。每步继续消耗精神和体力，强制搬运保留原有透支与痛苦记录。

重新构建后重启新版应用生效，不需要更新数据库结构；聊天记录、工资及已有进度不重写。

## 搬砖任务与工钱

在饭钱页面直接录入任务趟数和总工钱；聊天可以自由讨论，但不会自动创建或修改任务。新增任务按顺序等待，当前任务完成或取消后下一份可工作；暂停时队列等待。未结清的工钱不会阻挡新增任务或后续工作，可以在各份历史任务下分别付款。新增、调整、取消和付款会作为事实进入她的认知；是否工作由她结合自己的状态决定，实际趟数以动作回执为准。
