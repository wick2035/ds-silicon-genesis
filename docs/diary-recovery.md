# 日记材料预算与补写恢复

日记材料按香港日期筛选，保留发言身份、真实感受及其来源。24,000 字符上限涵盖正文、关联发言、身份字段和完整 JSON 开销。优先压缩摘录与关联发言数量，仍超限则交替选取感受、对话和具体经历；保留完整事件编号，不截断 JSON，不删除原始记录。日记和成长反思共用这套材料控制。

新宿主持有独占写入租约后，将上次中断的整理领取标记为失败，允许手动重试；不会因此重复自动调用模型。生成成功后沿用原事务保存日记、来源和费用，失败不保存半篇日记，也不扣日记饭钱。

模型看到的事件和关联发言使用本次请求内的短来源编号，由宿主精确还原为真实事件编号；实际展示过的 `speakers` 发言也可独立引用。不会接受未展示的来源、猜测哈希或丢弃错误编号后强行保存。JSON 或来源编号不合格时，在同一次领取与正常模型预算内最多纠正一次，仍失败则保存失败原因，供手动重试；网络错误不自动重试。最终保存前仍重新检查原始事件是否存在或已撤回，日记费用只在保存成功的事务中结算一次。

明确授权的一次性修复可存于私有 `data/authorized-repairs.json`，格式为 `{version:1,petId,tasks:[...]}`。任务使用 `status:"pending"`，旧碗任务为 `{kind:"discard-meal",actionId,itemId,requestId}`，日记任务为 `{kind:"diary",date:"YYYY-MM-DD"}`。

下次启动取得独占写入租约后，先把完整生命信封与该宠物的 outbox 备份到 `data/backups/`，再结清指定旧碗；应用就绪后通过正常日记服务补写指定日期。已有日记直接跳过。任务结果保存在原授权文件中；模型失败或中断后不在每次重启时反复调用，用户可在界面核对并手动重试。作废任务可安全重复结清。没有该私有文件时不执行一次性修复，不包含任何用户专属编号或固定补写日期。

无需数据库表结构迁移。授权文件、备份、模型内容和真实存档不提交 Git。

验证：生产构建；每日材料、身份归属、来源编号还原、一次纠正上限、撤回来源、失败重试、单次扣费、启动备份及中断恢复测试。真实模型回放使用内存副本；正式补写通过正常日记服务及费用，可用运行中应用的手动补写接口，或在重启新版后执行已授权的启动任务。
