# 冰箱与进食结果核对

生命空间的「饭钱 → 冰箱与熟饭」显示冰箱饭与锅饭的可用、进食中和待核对状态。只有待核对项提供「核对结果」和「作废这碗」。作废保留购买及原未知回执，另记一笔取消结清；饭钱和身体数值不变，旧碗不再占库存容量，不会被选来再次进食。

桌面主进程在发送进食终态前，将回执原子保存到私有 `data/runtime/meal-receipts/`。宿主收到迟到回执、执行转为未知或下次启动时，通过原动作和碗编号对账。回执重送不重播动画，重复确认不重复扣库存或增加身体收益。恢复的历史完成回执只核销库存，不把旧饭补加到当前身体；正常完成仍按实际进食结算。

没有可信终态证据时不会推断已经吃完。可保留待核对状态，或由爸爸在界面选择作废。作废与迟到确认沿用同一写入租约和事务，先提交的结清结果生效，后来的证据不能再次结算。

扩展现有 `/api/life/finance`：GET 的 `food` 返回饭的编号、来源、状态及相关动作；POST 接受 `{kind:"rice-resolution",action:"reconcile"|"discard",actionId,itemId,requestId}`，沿用原鉴权与请求校验。

不改数据库表结构。回执、授权记录和备份均属于私有运行数据，不应提交或分享。构建后重新启动应用生效。

验证：生产构建；`tools/meal-recovery.test.mjs`、库存、锅饭、饭钱及照料回归；`tools/meal-finance-electron-smoke.cjs` 验证隐藏隔离窗口内的桌面/窄屏布局、网络失败、同编号重试及作废操作。
